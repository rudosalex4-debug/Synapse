# База данных

PostgreSQL 17 хранит профили и компетенции, каталог тем, сессии, вопросы, отклики, диалоги и сообщения, правила участия, жалобы и очереди событий.

## Миграции и начальные данные

`max-help migrate` применяет SQL из `migrations/`, `max-help seed` загружает действующий каталог из `data/taxonomy.example.json`. Оба шага включены в штатные скрипты запуска. В учебном окружении создаются вымышленные Анна и Борис; реальные MAX-аккаунты создаются после проверки входа.

В поставке 11 файлов миграций:

- `001`–`004`: пользователи, каталог, сессии, устойчивые очереди и индексы подбора.
- `005_workflow.sql`: вопросы, отклики, диалоги, блокировки, жалобы и идемпотентность.
- `006_bot_forms.sql`: формы бота.
- `006_learning_outcome.sql`: учебный результат общения.
- `007_product_notifications.sql`: настройки продуктовых уведомлений.
- `008_matching_notifications.sql`: задания адресного подбора для уведомлений.
- `009_moderation.sql`: решения по жалобам и журнал доступа.
- `010_community_rules.sql`: явное согласие с версией правил.

Идентификатор миграции — полное имя файла. Два файла с номером `006` имеют разные имена: переименовывать их нельзя. Runner сохраняет SHA256, нормализует окончания строк, применяет каждый новый файл транзакционно и отклоняет изменение уже применённой миграции.

## Данные и резервные копии

Учебный стенд жюри и рабочий MAX-сервер используют разные Docker-проекты и тома. `stop` сохраняет данные. Не удаляйте том базы для исправления ошибки миграции.

Рабочий `pilot.sh deploy` создаёт дамп перед миграциями; дампы и локальные настройки хранятся в исключённом из Git каталоге `private/`. Пароль рабочего PostgreSQL генерируется при подготовке окружения. Пароли в локальных Compose предназначены только для изолированных учебных и тестовых баз.
