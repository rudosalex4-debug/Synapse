# Синапс · Synapse

**Адресная взаимопомощь в учёбе и карьере - бот и мини-приложение MAX.**

Синапс помогает обратиться к человеку, который уже проходил похожий этап: выбирал программу обучения, участвовал в олимпиаде, занимался исследованием или устраивался на стажировку. Пользователь описывает вопрос и уточняет тему, а подходящие участники видят его и добровольно предлагают помощь.

Приоритет MVP - школьники перед выбором образовательного пути и студенты, которым нужен опыт поступления, практики или первой работы. Выпускники и специалисты могут делиться пройденным опытом и сами обращаться за помощью.

У каждого один профиль: можно спрашивать о незнакомом и отвечать там, где есть собственный опыт. Для первого вопроса не требуется заранее становиться помощником.

## Быстрый запуск для жюри

Склонируйте репозиторий по ссылке из заявки или распакуйте архив исходников. Откройте терминал в корне полученной папки и выполните:

```bash
bash scripts/jury.sh up
```

Откройте **http://localhost:18080**, выберите учебного участника **Анну** или **Бориса** и примите правила участия.

Нужны работающий Docker с Compose **2.20+** и Bash: Linux, Windows через WSL или macOS. Первый запуск собирает приложение из исходников и требует доступа в интернет для загрузки зависимостей. Токен MAX, домен, `.env`, локальные Node.js и C++ не нужны.

- [Подробный локальный запуск и решение типовых проблем](docs/LOCAL_RUN.md).
- [Сценарий знакомства: вопрос → отклик → диалог → результат](docs/USER_GUIDE.md).

## Основной сценарий и ожидаемый результат

1. **Борис** принимает правила, добавляет знание «Образовательные траектории → Университеты → Выбор специальности и программы», включает готовность помогать и сохраняет профиль.
2. **Анна** принимает правила, создаёт вопрос «Как сравнить две университетские программы?» по той же теме, сохраняет черновик и публикует его. Для первого прохода дополнительные обязательные условия оставляют пустыми.
3. Борис открывает **«Могу помочь»**: вопрос Анны появляется в подходящей ленте с объяснением совпадения. Он отправляет отклик; диалог ещё не открыт.
4. Анна выбирает Бориса среди откликнувшихся. **У обоих появляется один приватный диалог**; сообщения доступны только разрешённым участникам.
5. После переписки автор фиксирует итог и следующий шаг. **История сохраняется, завершённый диалог больше не принимает сообщения**.
6. Участники могут поменяться ролями в карьерном направлении, используя те же профили.

Откройте два окна браузера, например обычное и приватное. При необходимости обновляйте список. Точные поля и кнопки - в [руководстве](docs/USER_GUIDE.md).

## Окружение, данные и управление

| Область | Локальная проверка | Действующий MAX-сервер |
|---|---|---|
| Вход | Вымышленные Анна и Борис | Подписанные MAX `initData`, пользовательская сессия |
| Настройки | `.env` не нужен; `jury.sh` задаёт учебное окружение | Приватные `.env.max.local` и `.env.pilot.local`; шаблон [pilot.env.example](pilot.env.example) |
| Основные переменные | `DEMO_MODE=true`, `PILOT_MODE=false`, доставка MAX выключена | `APP_ENV=production`, `DEMO_MODE=false`, `PILOT_MODE=false`, `APP_PUBLIC_URL`, `MAX_BOT_TOKEN`, `MAX_BOT_USERNAME`, `MAX_WEBHOOK_SECRET`, `POSTGRES_PASSWORD` |
| Дополнительные переменные | Порт передаётся аргументом `jury.sh up 18081` | `PILOT_PORT`, `MODERATOR_MAX_IDS`, `MAX_PRODUCT_NOTIFICATIONS_ENABLED`; allowlist нужен только для закрытого режима |
| Порты | `127.0.0.1:18080`; внутри backend `8080`, PostgreSQL `5432` | Публичный HTTPS `443` → backend `127.0.0.1:8085`; БД наружу не публикуется |
| Хранение | Отдельный том PostgreSQL проекта `synapse-jury` | Отдельная рабочая база проекта `synapse-pilot` и приватные резервные копии |
| Внешние сервисы | Отправка в MAX отключена; интернет нужен для сборки. Библиотека Bridge загружается с CDN MAX; учебный вход доступен и без неё | MAX Bot API и MAX Bridge; нужен действующий бот, привязанный URL mini-app, HTTPS и webhook |

Начальный каталог загружается автоматически; профили, вопросы, сообщения и результаты сохраняются в PostgreSQL. На свежем локальном стенде создаются Анна и Борис, а компетенции и вопросы жюри добавляет по сценарию выше. `data/demo-scenarios.json` - синтетические описания сюжетов, не готовый seed переписки и не готовые тела запросов API. Каталог не является актуальным реестром вакансий или образовательных программ.

```bash
bash scripts/jury.sh status
bash scripts/jury.sh logs
bash scripts/jury.sh stop
# Повторный запуск с сохранённой учебной базой:
bash scripts/jury.sh up
```

Остановка сохраняет данные. После обновления исходников повторный `up` собирает их, применяет миграции и каталог; не удаляйте том базы для обновления. Для нестандартного порта повторяйте выбранный аргумент: `bash scripts/jury.sh up 18081`.

Зависимости сборки: **Node.js 24, pnpm 11.19.0, React 19, TypeScript 5.9, Vite 7, C++20/CMake, Drogon, OpenSSL, libcurl, libpq, PostgreSQL 17**. JavaScript-зависимости зафиксированы в [pnpm-lock.yaml](pnpm-lock.yaml); native-пакеты и базовые образы задаются в [Dockerfile](infra/Dockerfile). apt-пакеты и Docker-теги не закреплены до точных digest/версий: побитовая воспроизводимость не заявляется. Ни один внешний платный API/LLM для основного сценария не нужен.

## Что можно сделать

- **Собрать профиль знаний:** выбрать тему, уточнить контекст, описать опыт и готовность помогать. Ссылки на свидетельства опыта необязательны и отмечаются как непроверенные.
- **Задать адресный вопрос:** сохранить черновик, указать цель, выбрать обязательные условия подбора и отдельно опубликовать вопрос.
- **Понять основания подбора:** увидеть совпадение темы, уточнений и вида опыта. Предварительный подбор показывает текущую доступность подходящих участников.
- **Предложить помощь:** открыть подходящий вопрос в разделе «Могу помочь» и описать, чем сможете помочь. Автор выбирает одного собеседника из откликнувшихся.
- **Обсудить вопрос:** переписываться в приватном диалоге, завершить его с итогом и следующим самостоятельным шагом.
- **Управлять участием:** приостановить помощь, ограничить число активных диалогов, настроить уведомления MAX, заблокировать собеседника или отправить жалобу.

Бот и мини-приложение работают с одним профилем и вопросами подтверждённого пользователя MAX. В боте доступны пошаговые формы вопроса и знания; мини-приложение объединяет профиль, подбор, отклики и переписку.

## Два направления MVP

| Направление | Темы |
|---|---|
| **Образовательные траектории** | Университеты, школы и лицеи, колледжи и СПО, олимпиады, научная работа, хакатоны, курсы, дополнительное образование, специальности, стипендии, академическая мобильность. |
| **Карьера** | Работа и первая практика, стажировки, компании, вакансии и их требования, профессии, резюме и собеседования, смена профессии, развитие специалиста. |

Выбор идёт от направления **L1** к теме **L2** и при необходимости к более точной ситуации **L3/L4**. Конкретные вуз, программа, компания и другие обстоятельства задаются отдельно. Например: **Образовательные траектории → Университеты → Выбор специальности и программы**, затем нужный вуз и уровень обучения.

В карьерном направлении участники обсуждают опыт и подготовку: размещение вакансий, найм и платные услуги в MVP не входят.

## Как вопрос находит помощника

Сервер отбирает кандидатов по теме и её уточнениям, затем сопоставляет контекст с конкретным знанием участника. Обязательные условия должны совпасть; также учитываются готовность помогать, текущая нагрузка и блокировки. Более узкое знание отмечается отдельно. Свойства разных знаний человека не склеиваются в несуществующую компетенцию.

Для отбора используются индексы тем и ограниченные выборки кандидатов. Предварительная проверка охватывает до **1000 компетенций** и сообщает, если выборка ограничена. Результат объясняет соответствие указанному опыту; он не удостоверяет квалификацию и не гарантирует отклик.

## Использование в MAX

Ссылка на развернутого бота передаётся вместе с заявкой. Откройте бота, нажмите «Начать» или отправьте `/start`, затем откройте мини-приложение.

Публичное серверное окружение допускает **любого пользователя с подтверждённым входом MAX**: добавление в список приглашённых не требуется. Подпись данных входа проверяет сервер; личные данные, действия участников и полномочия модератора ограничиваются отдельно.

Локальный режим Анны и Бориса использует вымышленных участников. Он позволяет пройти продуктовый сценарий без MAX, но не воспроизводит реальный вход, команды и доставку уведомлений в мессенджере. Для них нужен отдельный сервер с HTTPS и настройками своего бота.

## Ограничения и следующий контекст применения

- Помощь добровольная: совпадение опыта не гарантирует ответ. Подтверждения компетенций не проходят автоматическую независимую проверку.
- Свежая учебная база не содержит готовых диалогов. Реальные MAX-вход, бот, webhook, уведомления и роль назначенного модератора воспроизводятся в рабочем HTTPS-окружении.
- Внешние базы вакансий, дипломов и университетов не подключены. Автоматический ИИ-наставник, платные услуги и общая лента публикаций в MVP не входят.
- Лимит сборки из задания - до пяти минут без первоначального скачивания базовых образов - для этого пакета **не измерен**. Успешный запуск и результаты CI этой копии не заявляются без отдельного прогона.

Следующий шаг внедрения - одно студенческое сообщество: привлечь участников с опытом поступления и стажировок, назначить модераторов и наблюдать время до подходящего отклика, долю вопросов с диалогом и долю завершённых обращений. Это план оценки, а не уже полученная статистика.

После такого пилота тот же сценарий можно перенести в другое учебное сообщество: сохранить профиль, вопрос, отклик и диалог, адаптировать темы/контекст, состав участников и правила. Для отдельной организации возможна независимая установка со своей базой; корпоративная многопользовательская изоляция организаций внутри одного экземпляра пока не реализована. [Архитектура и условия масштабирования](docs/ARCHITECTURE.md).

## Устройство и документация

**Backend:** C++20 / Drogon. **Интерфейс:** React / TypeScript. **Данные:** PostgreSQL 17. **Развёртывание:** Docker Compose.

HTTP-сервер и фоновый обработчик используют общий код и базу. Входящие события бота и исходящие сообщения сохраняются в очередях PostgreSQL; изменения схемы применяются миграциями. Запись профиля защищена от перезаписи устаревшей версией, а повторяемые действия API используют ключи идемпотентности.

| [Руководство пользователя](docs/USER_GUIDE.md) | Путь автора вопроса и помощника, смена ролей. |
| [Развёртывание в MAX](docs/DEPLOYMENT.md) | HTTPS, приватные настройки, открытый доступ и обновление сервера. |
| [Доступ к API](docs/API.md) | Получение сессии, авторизация и использование контракта. |

| [OpenAPI](openapi.json) | Машиночитаемый контракт HTTP API. |

Исходники приложения находятся в `apps/`, общий контракт интерфейса - в `packages/`, каталог тем - в `data/`, миграции - в `db/migrations/`, сценарии запуска - в `scripts/` и `infra/`.

В репозиторий не входят рабочие пароли, токены, идентификаторы участников, настройки действующего бота и дампы пользовательской базы. Шаблоны окружения заполняются владельцем установки. Автоматические тесты и CI сохранены в исходниках; подготовка этого пакета не означает подтверждения их прохождения.
