# Настройки доступа и конфиденциальность

## Что хранить вне Git

Реальные токены MAX, пароль рабочей БД, секрет webhook, приватные ключи, выданные сессии API, списки MAX ID пользователей/модераторов, дампы, журналы с пользовательскими данными и локальные env-файлы не входят в поставку.

Шаблоны `.env.example` и `pilot.env.example` не содержат рабочих секретов. Имя бота задаётся владельцем через `MAX_BOT_USERNAME`; в комплекте нет имени или числового ID рабочего бота. Публичную ссылку на действующий бот владелец передаёт организаторам отдельно.

Для настроек используются игнорируемые `.env.max.local`, `.env.pilot.local` и `private/`. Правила `.gitignore` и `.dockerignore` исключают их из обычного добавления в Git и сборочного контекста. Не используйте `git add -f` для таких файлов и не добавляйте токен в командную строку, README, URL или скриншоты. После создания своего репозитория перед коммитом просмотрите состав индекса самостоятельно.

## Режимы приложения

- Рабочий сервер требует подписанные MAX `initData`. Общий доступ `PILOT_MODE=false` разрешает вход любому подтверждённому MAX-аккаунту, сохраняя права на его собственные данные.
- Демонстрационные Анна/Борис доступны только в локальном окружении. Production запрещает demo-вход.
- Сессии ограничены по времени; в базе хранится хеш токена. Выход отзывает переданную сессию.
- Модераторы назначаются только через локальную конфигурацию `MODERATOR_MAX_IDS`; открытый доступ не выдаёт права модератора.
- Подтверждение опыта по ссылке хранится как «не проверено». Приложение не заявляет автоматическую проверку дипломов или личности за пределами проверки MAX-входа.

Локальные пароли и ключи в тестовых примерах - синтетические значения для учебных окружений. Они не подходят для рабочего сервера. Их наличие не означает, что пользователям выдаётся доступ к рабочей базе.
