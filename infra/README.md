# Сборка и окружения

| Окружение | Команда из корня | Назначение |
|---|---|---|
| Жюри | `bash scripts/jury.sh up` | Отдельный локальный стенд на порту 18080, учебный вход, без токена MAX |
| MAX | `bash scripts/pilot.sh deploy` | HTTPS-развёртывание с реальными MAX-аккаунтами и отдельной рабочей базой |
| Разработка | `docker compose up --build -d` | Локальный developer Compose на порту 8080; обычная сборка включает тесты |

Жюри: [пошаговый запуск](../docs/LOCAL_RUN.md). Сервер: [настройка и обновление](../docs/DEPLOYMENT.md).

`Dockerfile` собирает React через Node.js 24 / pnpm и C++20 через CMake/Ninja в отдельных этапах. Runtime содержит нативный backend, worker, готовые файлы интерфейса, SQL-миграции и каталог. Node не обслуживает HTTP API.

Штатные скрипты жюри и рабочего развёртывания передают `RUN_TESTS=false`: компиляция и проверка типов остаются, тесты не запускаются. Сборка без этого аргумента по умолчанию выполняет тесты. Время первой сборки зависит от сети, доступности системных пакетов и ресурсов машины; ограничение времени из задания отдельно не подтверждено.

Приложение работает под непривилегированным пользователем, с read-only файловой системой и временным `/tmp`. PostgreSQL не публикуется на внешнем интерфейсе. Рабочие секреты передаются при запуске, не входят в образ и не копируются в исходники.

`init-db.sh` выполняет миграции и загрузку каталога до запуска приложения. `Caddyfile.pilot.example` - шаблон HTTPS-прокси, который адаптируется к вашему домену и локальному порту.
