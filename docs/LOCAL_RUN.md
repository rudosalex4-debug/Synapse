# Локальный запуск для жюри

Это отдельное учебное окружение Синапса с двумя вымышленными участниками. Можно самостоятельно пройти путь от вопроса до переписки и результата. Домен и учётная запись MAX для этого режима не нужны.

## Требования

- Docker с плагином Compose версии **2.20 или новее**; Docker Engine должен быть запущен.
- Bash: Linux, Windows через WSL или macOS.
- Доступ в интернет при первой сборке для загрузки образов и зависимостей.
- Свободный локальный порт **18080** или другой выбранный порт.

Отдельно устанавливать Node.js, pnpm, компилятор C++, PostgreSQL и создавать `.env` не требуется: сборка и сервисы работают в контейнерах.

## Запуск

1. Получите исходники по ссылке на репозиторий из заявки либо распакуйте предоставленный архив.
2. Откройте Bash в корне полученного проекта, где находятся `compose.jury.yaml` и папка `scripts`.
3. Выполните:

```bash
bash scripts/jury.sh up
```

4. Дождитесь адреса `Local jury demo: http://localhost:18080` и откройте его в браузере.
5. В разделе «Мои знания» выберите Анну или Бориса и нажмите «Открыть учебный профиль».
6. Примите правила участия перед сохранением профиля, публикацией вопроса или откликом.

Скрипт собирает frontend и C++ backend, поднимает PostgreSQL, применяет миграции и каталог, затем запускает сервер и фоновый обработчик. Он не запускает наборы тестов; проверка типов и компиляция входят в сборку.

На первом запуске загрузка и сборка занимают больше времени. Повторный запуск использует Docker-кеш и сохраняет учебные данные. После ошибки сборки прочитайте её вывод; приложение не считается запущенным до успешного завершения команды.

### Если порт занят

Укажите другой порт:

```bash
bash scripts/jury.sh up 18081
```

Адрес будет **http://localhost:18081**. При последующих вызовах `up` с этим окружением снова указывайте выбранный порт; без аргумента используется 18080.

## Пройти сценарий вдвоём на одном компьютере

Откройте приложение в двух отдельных окнах браузера, например обычном и приватном. В первом войдите Анной, во втором - Борисом. Участники используют одну учебную базу, поэтому вопрос, отклик и сообщения доступны второй стороне.

Для API-проверки подготовлены [JSON-данные и учётные записи Анны и Бориса](API_TEST_DATA.md). Они используют ту же локальную БД; данные сценария загружаются через API.

Полная последовательность - в [руководстве пользователя](USER_GUIDE.md). Вопросы и знания для демонстрации создаются явно по этой инструкции: наличие заранее заполненных диалогов не предполагается.

После перезагрузки страницы может потребоваться снова выбрать учебного участника. Сохранённые сервером данные остаются в базе; несохранённый текст формы не считается сохранённым черновиком.

## Управление

Из корня проекта:

```bash
# Контейнеры и фактический порт приложения
bash scripts/jury.sh status

# Последние сообщения сервера и фонового обработчика
bash scripts/jury.sh logs

# Остановка с сохранением учебной базы
bash scripts/jury.sh stop

# Повторный запуск
bash scripts/jury.sh up
```

Для нестандартного порта повторный запуск выполняется с его номером, например `up 18081`.

## Изоляция учебного окружения

- Используется отдельный проект Docker Compose **`synapse-jury`** и собственный том PostgreSQL.
- Приложение доступно только на локальном интерфейсе компьютера. PostgreSQL не публикует порт на хост.
- Скрипт не читает рабочие `.env`-файлы и не использует токен MAX.
- Вход Анной/Борисом разрешён только в учебном окружении. Внешний сервер использует настоящий вход MAX.
- Доставка сообщений и уведомлений в MAX в этом режиме выключена. Приватная переписка внутри приложения доступна.
- Учебные участники общие для этой локальной базы; вводите только вымышленные сведения.

Команды не затрагивают базу серверного проекта `synapse-pilot`. Не объединяйте `compose.jury.yaml` с другими Compose-файлами.

## Частые ситуации

| Что произошло | Что сделать |
|---|---|
| Docker недоступен | Запустите Docker Engine и проверьте доступ к нему из того же Bash/WSL, где выполняете команду. |
| Порт занят | Запустите `bash scripts/jury.sh up 18081` и откройте соответствующий адрес. |
| Не открывается страница | Дождитесь окончания запуска, посмотрите `status` и `logs`, используйте порт из `status`. |
| Подходящих вопросов нет | Сохраните совпадающую тему в профиле помощника, включите «Готов(а) помогать», примите правила у обоих участников и опубликуйте вопрос. Затем нажмите «Обновить». |
| Появилась ошибка повторного входа | Восстановите вход с экрана приложения или снова выберите того же учебного участника; сохранённые вопросы останутся в базе. |
| Бот не отвечает | Учебный запуск не подключается к MAX. Для настоящего бота используйте [инструкцию развёртывания](DEPLOYMENT.md). |

Контракт и порядок работы с API описаны в [документе API](API.md).
